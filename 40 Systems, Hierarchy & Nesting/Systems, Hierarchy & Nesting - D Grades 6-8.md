# Systems, Hierarchy & Nesting — Band D (Grades 6–8, ages 11–13)

**Core idea:** software is organized the same nested way — a module contains packages, a package contains functions — and the same "box inside a box" pattern shows up across every strand in this curriculum.

**Spiral note:** builds on [[Systems, Hierarchy & Nesting - C Grades 3-5]] — file paths and biological classification were two concrete examples; this band adds software's module/package/function hierarchy and class hierarchies, then names the pattern explicitly as a crosscutting idea: atoms-in-molecules ([[Matter & Energy - D Grades 6-8]]), cells-in-organisms ([[Life & Living Systems - D Grades 6-8]]), classes-in-hierarchies, and tags nesting inside tags in HTML ([[Information & Communication - D Grades 6-8]]) are all the same shape.

## Hands-on activities
- Walk through a real, simple codebase folder structure (or a visual block-coding project) and identify module → package → function nesting.
- Sketch a class hierarchy for a familiar set of objects (e.g., Vehicle → Car → SportsCar) and discuss what each level "inherits" from the one above.
- Build a single diagram putting the file path, biological classification, and software hierarchy side by side, and ask the child to name what's the same about all three.
- Revisit [[Systems, Hierarchy & Nesting - A PreK-K]]'s nesting dolls as the very first version of this same idea.
- Introduce SI prefixes (milli, kilo, mega, nano, giga...) as a nested naming system for scale itself — each step is another factor of 1000, the same "zoom in/zoom out" idea as the file-path and classification trees, just applied to numbers instead of folders or species.

## Vocabulary

Words this band uses, defined the way we'd describe them to someone who'd never seen them — what happens, not how it feels:

- **Hierarchy** — a nested-ordering pattern, narrow inside wide, that shows up the same way across different kinds of content.
- **Inherit** — keeping everything a wider level already has, then adding something more specific on top.
- **Module / package / function** — nested levels of a software project, each one holding the next: a project holds modules, a module holds functions.
- **Prefix** (as in *kilo-*, *milli-*) — a fixed label added to a unit name that multiplies or divides it by a set factor, usually a power of a thousand.

## Draft

### Inside a Real Codebase

Walk through a real, simple code project together (even a block-coding project like Scratch has an equivalent) and find the same nesting pattern as the file-path lesson: a project contains modules, a module contains functions, a function contains individual steps. Ask the child to find the narrowest thing first — a single line or block — and work outward, naming each wider layer it sits inside.

### What a Sports Car Inherits

Sketch a simple class hierarchy — Vehicle at the top, Car below it, SportsCar below that — and ask: "what does every Car have that every Vehicle has? What does a SportsCar have that a regular Car doesn't?" The idea to land on: each narrower level keeps everything the wider level had, and adds something more specific on top — the same shape as golden retriever keeping everything "dog" and "mammal" and "animal" already gave it, from [[Systems, Hierarchy & Nesting - C Grades 3-5]].

### One Diagram, Three Domains

Draw a single diagram with the file path, the animal classification tree, and the software class hierarchy side by side, top to bottom, narrow to wide. Ask the child to name out loud what's identical about the shape across all three, even though the content is completely different in each. Then pull the very first version of this idea back out — [[Systems, Hierarchy & Nesting - A PreK-K]]'s nesting dolls — and ask: "is this the same idea you had with the stacking dolls, just bigger?" Naming that callback explicitly is the point of the whole spiral, not just a nice touch.

### Zooming In and Out With Numbers

Introduce the SI prefixes — milli, kilo, mega, nano, giga, and however far you want to go — as a nested naming system for scale itself: each step is another factor of a thousand, the same "zoom in, zoom out" idea as the file path or the classification tree, just applied to numbers instead of folders or species. Ask the child to place a few familiar things on the scale (a millimeter is about the width of a pencil line; a kilometer is about a 10-minute walk) before handing them the full table to explore.
